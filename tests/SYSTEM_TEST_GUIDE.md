# 国缆杯学习/考试系统 v2 —— 系统级测试案例

> 目标：用一套可重复运行的端到端测试，保证"出卷正确性 / 判分零误差 / 答案零幻觉 / 前端可跑"
> 不依赖人工抽查，每次改完题库或前端都能一键回归。

## 1. 为什么需要这个测试案例

本系统有两条"绝对不能错"的生死线：

1. **判分必须 100% 确定、且与前端完全一致** —— 学员考完看到的分，必须和权威后端算的一模一样。
2. **答案必须零幻觉、可溯源** —— 每一道题都要能回查到具体标准条款，绝不能凭模型记忆编造。

人工抽查 123 道题既不可靠也不可重复。所以把校验写成 `tests/system_test.py`，
**它本身就是"对整个系统的测试案例"**：覆盖资产（题库/KU）→ 判分引擎（PY↔JS）→ 前端 SPA → 溯源。

## 2. 测试分层（T1～T7）

| 组 | 名称 | 校验什么 | 失败意味着 |
|----|------|---------|-----------|
| T1 | 结构齐备 | 目录/关键文件存在、可执行脚本能 import | 部署缺文件 |
| T2 | 题型契约 | 题库严格遵守 bank/2.0：仅 choice/judge/fill/calc 四型，每题带结构化 `src{standard_no,clause}` | 新增了 grade.js 不支持的题型（如 match 连线题会漏判）→ 前端分数算错 |
| T3 | 评分自检 | `generate.py compute_score()` 对"满分卷"得满分、"全错卷/空卷"得 0 分 | 评分公式 bug |
| T4 | 判分一致性(PY↔JS) | 同一份卷子分别用 Python 权威引擎与前端 grade.js 判分，逐题比对 | 前后端分数不一致（最危险的线上事故） |
| T5 | 溯源零幻觉 | 每题都有 src；src 标准号在 KU 库内；条款能回查到 KU | 出现标准号写错、条款号张冠李戴、或标准根本没入库的"幻觉题" |
| T6 | 前端 SPA 冒烟 | app.js 语法通过；grade.js 能判分；SPA 引用的数据文件齐全且可解析；rules/ 与 public/data/ 同步 | 上线后白屏、某个题库加载不出、或前端用的是旧版题库 |
| T7 | 资产覆盖度 | raw 文档数 / KU 数 / 题库数 / 题目数 / 已出题标准覆盖率达标 | 资料没吃全、题库太少没得练 |
| T8 | 后端服务冒烟 | 真实启动 `server.py`，HTTP 层验证 `/api/build` 按权重出卷、 `/api/grade` 判卷（满分=满分、全错=0） | 后端出卷/判卷挂了，线上考试出不了题或分数算错 |

- **FAIL** = 阻断级，必须修完才能部署。
- **WARN** = 已知覆盖缺口（如某标准判了 KU 但还没出题），不阻断但列入待办。

## 3. 怎么运行

```bash
cd learning-system-v2
python tests/system_test.py
```

输出三样东西：
- 终端：逐条 `[ ok ] / [warn ] / [FAIL]` 与末尾结论。
- `tests/report.json`：机器可读结果，便于 CI 解析。
- `tests/report.html`：人类可读的彩色报告，可直接打开/分享。

**判定门槛**：`FAIL == 0` 才算"可以部署"。

## 5. 加新标准后的回归流程（怎么用这个测试守住系统）

1. 把新 PDF 丢进 `kb/raw/`（doc2kb 抽取/OCR）。
2. 写/大模型判 KU → `kb/judged/_ku_docNN.json`。
3. 出题 → `rules/<new>.json`（必须 bank/2.0 四题型 + 结构化 src）。
4. 跑 `python kb/build_master.py` 重建 master。
5. 跑 `python tests/system_test.py`：
   - 若新题库用了 match 等非法题型 → T2 FAIL；
   - 若 src 标准号没进库 → T5 FAIL；
   - 若 rules 改了没同步前端 → T6 WARN。
6. 全绿后 `workbuddy_cloudstudio_deploy` 重新部署 `public/`。

## 6. 建议的下一步扩展（T8，可选）

当前 T1～T7 覆盖了"资产 + 判分引擎 + 前端消费"。若要测"整个后端服务"，可加：

- **T8 后端冒烟**：启动 `server.py`，对 `/api/build`（按权重出卷）、`/api/grade`（判卷落库）发请求，断言返回结构与分数正确。
  这能把"出卷器 / 闭卷考试 / 成绩"等服务器端功能也纳入回归。

> 注意：连线题(match)、简答题、问答题一律不允许进题库——grade.js 只认 choice/judge/fill/calc 四种，
> 其他题型前端会漏判分。这是架构红线，由 T2 守护。
